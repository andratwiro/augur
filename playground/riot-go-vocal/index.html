Why it matters

Two things at once.

For residents

A real voice, while it counts

A legitimate, verified way to be heard while the decision is still open — not a survey weeks later. Taking to the streets, digitally.

For councillors

The pulse, as you vote

A real-time read of the people you serve, at the exact moment it matters. A live feel for the room beyond it.

In the product

A new destination — not a project.

  • A “Council” item in the navbar. Its own standing page at /council — not a project, not a phase. A place that's always there.
  • Each plenary is an Event. Date, agenda, a public page, reminders — reusing what Go Vocal already does for events.
  • Verified sign-in gates the live vote. Real residents, one voice each — the identity stack already guarantees it.

Note: “Space” is already an internal Go Vocal term (an admin feature in development), so I'd name this resident-facing thing “Council,” not a “space.”

Clear-eyed

What's actually hard.

  • True real-time at plenary scale is a build. Today only Online Workshop is genuinely live; the rest refresh. Live-while-voting needs real infrastructure.
  • No councillor role exists yet. Go Vocal has admins and managers — not elected officials. The bench-side view is net-new.
  • Connecting each council is real work. Agenda, record, calendar — wired per chamber, not per tenant.

The first test

One council, one live session.

  1. Pick a council already on Go Vocal with a public agenda and record.
  2. Ship the destination: past summaries, one live session, what's upcoming.
  3. Put a tablet on the bench — give councillors the live pulse during one real plenary.
  4. Ask: did being heard in real time change anything — for residents, for the vote?

In one line

Today the city speaks before and after. This lets it speak during.

That's the whole bet.
