Start here

Connect your terminal

This workspace is built by briefing a coding agent on your own machine. Nothing to install here, nothing to configure. One connection and everything the agent writes shows up on this site.

Pick one

Unsure? Take the walkthrough. It skips anything you already have.

Path A

Run this where your agent runs

In the folder you want this workspace to live in, run:

npx augur connect your-workspace

A browser tab opens and asks you to approve the connection. Approve it and the terminal has a key of its own — your password never goes near the agent. The workspace lands in that folder, ready to edit.

The terminal prints the workspace it is connected to, and the folder now holds this site's screens as plain HTML files.
Rather have the agent do it?

Paste this into your agent instead of running the command yourself.

Run `npx augur connect your-workspace` in this folder. It will open a browser tab for me to approve — tell me when it is waiting, and tell me exactly what it prints when it finishes.
Then

Brief it like a designer

There is no editor here. You describe a screen, the agent builds it as a page in this workspace, and publishing puts it on this site. Your first brief can be this one:

Read skills/starter-ui/SKILL.md and the prototypes under start-here/prototypes/, then build a new one at sketches/prototypes/first-screen/index.html. It is [one or two sentences describing the screen you want]. Use the starter design system rather than inventing new styles, give it a one-line meta description, and publish it when it works.

Fill in the bracket with a real screen you need. Vague briefs make vague screens.

Path B

Fifteen minutes, five steps

2 + 5 + 3 + 2 + 3 min

Do them in order. Every step says what you should see when it worked — if you see something else, open the way out underneath it and paste the question to any assistant you can chat with. Each one is written to be answered cold, with no other context.

Your computer
Steps
  1. 1

    Open a terminal

    2 min

    Press ⌘ + Space, type Terminal, press Enter. It ships with the Mac; nothing to install.

    Press the Windows key, type PowerShell, press Enter. It ships with Windows; nothing to install.

    Press Ctrl + Alt + T, or find Terminal in your applications menu.

    A window with a blinking cursor, your username at the start of the line. Text only — that is correct.
    Stuck on this step?

    Paste this to any assistant you can chat with — a browser chatbot is fine.

    I'm on macOS and I have never used a terminal. I need to open the built-in terminal app and I can't find it. Tell me exactly where to click, one step at a time, and what the window should look like when it's open.
  2. 2

    Install Node.js

    5 min

    Node is the runtime the agent's command line needs. Check whether you already have it — type this and press Enter:

    node -v

    A version number of v20 or higher means you are done with this step. Anything else — command not found, or a lower number — install the current LTS release.

    Download the macOS installer from nodejs.org, open it, click through. Then close the terminal window and open a new one.

    Download the Windows installer (.msi) from nodejs.org, run it, keep the defaults. Then close PowerShell and open it again.

    Your package manager's version is often too old. Take the current LTS from nodejs.org or use nvm, then open a new terminal.

    node -v prints something like v22.11.0.
    Stuck on this step?

    Paste this, and add whatever the terminal actually said.

    I'm on macOS. I ran `node -v` in the terminal and it did not print a version number of v20 or higher. I need to install the current LTS release of Node.js and confirm it worked. Walk me through it one step at a time, assume I have never used a terminal, and tell me how to check it afterwards. Here is exactly what the terminal printed:
  3. 3

    Install a coding agent

    3 min

    Any agent that runs in a terminal and can read and write files works here. If you have no preference, install this one:

    npm install -g @anthropic-ai/claude-code

    Others exist and are equally fine — pick whichever you already pay for. The rest of this walkthrough assumes the one above; swap the command names if you chose differently.

    The terminal ends with something like added 1 package and gives you your prompt back.
    Stuck on this step?

    Permission errors on this step are common and harmless to fix.

    I'm on macOS. I ran `npm install -g @anthropic-ai/claude-code` and it failed instead of finishing. Explain what went wrong in plain language and give me the safest fix, one step at a time — I have never used a terminal, and I would rather not run anything with sudo unless you explain why it is needed. Here is exactly what it printed:
  4. 4

    Sign in to the agent

    2 min

    Start it. The first run walks you through signing in — a browser tab opens, you approve, you come back to the terminal.

    claude

    Once it is running, type a sentence and press Enter. It answers in the terminal. That is the whole interface — you are talking to it, not programming it.

    You type hello, it replies. Leave it running; the next step happens right here.
    Stuck on this step?

    Sign-in problems are the agent's, not this workspace's — ask about the agent.

    I'm on macOS. I installed the Claude Code CLI and typed `claude` in the terminal, but I could not get signed in. Explain what the sign-in flow is supposed to do, what to check, and how to start it again from scratch. Assume I am not technical. Here is what the terminal shows:
  5. 5

    Connect this workspace

    3 min

    Last one. Ask the agent to connect, in plain language — it runs the command for you:

    Run `npx augur connect your-workspace` in this folder. It will open a browser tab for me to approve — tell me when it is waiting, and tell me exactly what it prints when it finishes.

    Approve the tab that opens. The terminal now has a key of its own, so your password never goes near the agent, and this workspace's screens are files in that folder.

    The terminal prints the workspace it is connected to. You are done — everything from here is briefing, not setup.
    Stuck on this step?

    Paste this to the agent itself; it can read its own error.

    The connect command failed. Read the error carefully and tell me in plain language what it means, whether it is a problem on my machine or on the server, and what to try next. Do not run anything destructive. If it is a permissions or network problem, say so plainly.
